# Habit Tracker API

Backend-приложение для отслеживания полезных привычек, разработанное на Django Rest Framework (DRF). Проект включает интеграцию с Telegram-ботом для автоматической рассылки уведомлений по расписанию с использованием фоновых задач Celery и Redis.

---

## Инструкция по установке и запуску

### 1. Клонирование и подготовка окружения
```bash
git clone habit_tracker
cd habit_tracker

# Создание и активация виртуального окружения
python -m venv .venv
source .venv/bin/activate  # Для Linux/macOS
# .venv\Scripts\activate  # Для Windows
```

### 2. Установка зависимостей
```bash
pip install -r requirements.txt
```

### 3. Настройка переменных окружения
Создайте файл `.env` в корневом каталоге проекта на основе предоставленного шаблона `.env.template`:
```bash
cp .env.template .env
```
Заполните параметры в `.env`: SECRET_KEY, настройки базы данных (если применимо) и TELEGRAM_BOT_TOKEN.

### 4. Миграции и создание суперпользователя
```bash
python manage.py makemigrations
python manage.py migrate
python manage.py createsuperuser
```

### 5. Запуск сервисов

Для полноценной работы проекта необходимо открыть 3 независимых терминала и запустить следующие процессы:

* Терминал 1 (Django Server):
  ```bash
  python manage.py runserver
  ```
* Терминал 2 (Celery Worker):
  ```bash
  # На Linux/macOS:
  celery -A config worker --loglevel=info
  # На Windows:
  celery -A config worker --loglevel=info -P solo
  ```
* Терминал 3 (Celery Beat Scheduler):
  ```bash
  celery -A config beat --loglevel=info
  ```

## Описание архитектуры и бизнес-логики

### Бизнес-правила привычек
Концепция основывается на формуле: я буду [ДЕЙСТВИЕ] в [ВРЕМЯ] в [МЕСТО]. Привычки делятся на полезные и приятные (используются как вознаграждение).

### Реализованные валидаторы (Бизнес-ограничения)
1. Исключение дублирования наград: Нельзя одновременно заполнить поле текстового вознаграждения (reward) и связанной привычки (related_habit).
2. Ограничение времени: Время на выполнение (duration) ограничено максимумом в 120 секунд (2 минуты).
3. Фильтрация связей: В поле related_habit могут быть добавлены исключительно те привычки, у которых установлен флаг is_pleasant=True.
4. Ограничение приятных привычек: У приятной привычки (is_pleasant=True) не может быть собственной связанной привычки или текстового вознаграждения.
5. Ограничение периодичности: Привычку нельзя выполнять реже, чем 1 раз в 7 дней (periodicity <= 7).

### Пагинация
Списки привычек разбиваются постранично — строго по 5 записей на страницу. Структура JSON-ответа включает стандартные метаполя DRF: count, next, previous и results.

### Права доступа (Permissions)
* Модификация данных (CRUD) разрешена исключительно создателю привычки (IsOwner).
* Эндпоинт публичных привычек доступен всем авторизованным пользователям в режиме ReadOnly.

## Эндпоинты API

* POST /api/register/ — Регистрация нового пользователя.
* POST /api/token/ — Авторизация (получение JWT access/refresh токенов).
* POST /api/token/refresh/ — Обновление JWT-токена.
* GET /api/habits/ — Список привычек текущего авторизованного пользователя (с пагинацией).
* POST /api/habits/ — Создание новой привычки.
* GET /api/habits/{id}/ — Просмотр конкретной привычки пользователя.
* PUT/PATCH /api/habits/{id}/ — Редактирование привычки.
* DELETE /api/habits/{id}/ — Удаление привычки.
* GET /api/public/ — Список всех публичных привычек системы доступных для примера (с пагинацией).

## Интеграция с Telegram и Celery

* Celery Beat каждую минуту сканирует базу данных на наличие привычек, чье время выполнения совпадает с текущим моментом.
* Асинхронный воркер отправляет структурированное текстовое сообщение в Telegram пользователю, если в его профиле привязан корректный telegram_chat_id.

## Безопасность и CORS
